# Раскраска (Nuxt 4)

Веб-версия детской раскраски. Проект в разработке; полный README (архитектура, модель хранения, ограничения, доступы, работа с ИИ) будет к сдаче.

## Локальный запуск

Требования: Node.js 24 (`nvm use`), pnpm 10 (`corepack enable pnpm`).

```bash
pnpm install
pnpm dev            # http://localhost:3000
```

## База данных и вход

Neon Postgres + Drizzle, вход игрока по имени и стране без пароля, вход администратора по логину и паролю из окружения.

```bash
cp .env.example .env     # заполнить DATABASE_URL, DATABASE_URL_UNPOOLED, NUXT_ADMIN_LOGIN, NUXT_ADMIN_PASSWORD
pnpm db:migrate          # применить миграции к ветке Neon из DATABASE_URL_UNPOOLED
pnpm db:seed             # три встроенных арта (идемпотентно, обновляет существующие)
pnpm dev                 # NUXT_SESSION_PASSWORD создастся в .env при первом запуске
```

- `DATABASE_URL` — pooled-строка Neon (приложение), `DATABASE_URL_UNPOOLED` — прямая строка (только миграции).
- Новая миграция: изменить `layers/core/server/db/schema.ts`, затем `pnpm db:generate` и закоммитить SQL.
- Тесты серверной логики идут на PGlite (Postgres в памяти) с теми же миграциями и не трогают настоящую базу.
- На Vercel миграции и сид применяются при каждой сборке (`vercel.json`): превью-ветка Neon получает схему своего PR, продакшен — свою. Вручную нужны только `NUXT_SESSION_PASSWORD` (не короче 32 символов), `NUXT_ADMIN_LOGIN` и `NUXT_ADMIN_PASSWORD`.

## Проверки

```bash
pnpm typecheck      # vue-tsc через nuxi
pnpm lint           # ESLint (+ границы слоёв)
pnpm lint:css       # Stylelint (mobile-first: только min-* медиа)
pnpm test           # Vitest: unit + nuxt
pnpm test:e2e       # Playwright: телефоны в альбомной ориентации, планшет, desktop
```

WebKit-проекты Playwright на Windows локально выключены: WebKit под Windows применяет системное масштабирование экрана к эмулируемому viewport. В CI (Linux) они работают; локально включаются через `PW_WEBKIT=1`.

## Структура

```
layers/core/       общая платформа: оболочка, «игровой режим», реестр игр
layers/coloring/   мини-игра «Раскраска»
shared/            типы и утилиты, общие для клиента и сервера
tests/             unit, nuxt, e2e
```

Игры регистрируются через `app.config.ts` своего слоя (`games.<id>`). Core строит навигацию по реестру и не импортирует код игр, это проверяет ESLint.

## Решения и допущения

- **Импорт SVG выполняется на сервере и не хранит исходную разметку.** Файл превращается в собственный формат: области (`region`) и линии (`ink`) с проверенными данными путей. Скрипты, ссылки, внешние ресурсы и DTD отбрасываются по построению.
- **Что считается областью.** Светлая заливка, а также замкнутый контур без заливки (типичный рисунок пером в Figma). Тёмные заливки (яркость ≤ 0.2) и обводки считаются линиями рисунка. Первая фигура на весь холст (заливка фрейма Figma) становится фоном: его можно красить, но в прогресс он не входит.
- **Линии поверх краски.** Рисунок накладывается на слой краски в режиме `multiply`: контур всегда виден, а исходный порядок слоёв сохраняется.
- **Базовые арты в векторе.** В макете осьминог — растровая картинка (PNG), а экспорт в SVG из Figma просто заворачивает этот PNG в `<image>`, областей в нём нет. Поэтому осьминог перерисован в векторе по образцу из макета. Кошку и дом (в макете их нет) нарисовали в том же стиле. Если появятся векторные оригиналы, файлы заменим.

- **Галерея.** Карточки идут новыми сверху (`seq`, keyset без `OFFSET`), по 12 на страницу, подгрузка по прокрутке. Встроенные арты видны всем, импорт только владельцу; чужой id отвечает 404, как и несуществующий. Миниатюра — SVG, который сервер собирает из нашего нормализованного арта (`/api/coloring/arts/:id/preview.svg`), исходный файл нигде не хранится и не отдаётся. Миниатюры закрашенного (PNG в Blob) появятся вместе с историей.
- **Импорт.** Файл уходит сырым телом, сервер читает его как UTF-8 (`TextDecoder` с `fatal`), прогоняет через конвейер и сохраняет. Название берётся из имени файла. Лимит 20 импортов на игрока проверяется перед вставкой отдельным запросом (драйвер Neon HTTP без транзакций), поэтому при параллельных запросах возможен небольшой перелёт; маршрут ограничен по частоте.
- **«Начать заново»** добавляет попытку (`progress.attempt + 1`) с нулевым прогрессом, старая остаётся. До первой попытки действия нет. Рамка карточки показывает процент последней попытки.
- **Рамка прогресса** — SVG-путь по размеру карточки, старт в середине левой стороны (180°), заполнение по часовой стрелке (по просьбе заказчика при проверке шага 6; изначально ТЗ предполагало против часовой).
- **Редактор.** Арт открывается через `GET /api/coloring/arts/:id` (те же правила видимости, что у миниатюры). Справа три инструмента и три последних цвета: выбранный цвет всегда нижний, нажатие на него открывает все 32 цвета, выбор закрывает список. Неактивные карандаши выдвинуты за край экрана, видно только кончик. Все анимации идут по `transform`/`opacity`, при `prefers-reduced-motion` отключены.
- **Прозрачность** 100/75/50/25 % переключается одной кнопкой слева и записывается в операцию (`opacity`, у резинки её нет). Штрих кисти при неполной непрозрачности собирается на промежуточном холсте целиком, поэтому перекрытия внутри одного штриха не темнеют. Краска засчитывается в прогресс от альфы ≈ 24 %, то есть и самая бледная.
- **Заливка удержанием** остаётся мгновенной: у пальца замыкается кольцо (450 мс), в момент заливки по цвету расходится круг (250 мс). Это оверлей поверх уже закрашенной области, а не реальное «раскрытие» самой краски. При `prefers-reduced-motion` остаётся только кольцо.
- **Отмена и возврат** в редакторе пока живут в памяти вкладки (после перезагрузки рисунок пустой): сохранение, чекпоинты и синхронизация идут в шаге 7.
- **100 %:** рамка встряхивается, при `prefers-reduced-motion` вместо этого мягко светится.

## Отклонения от макета

- **Меню «⋯» на карточке** (удалить, начать заново) в макете нет: действия нужны по ТЗ, а места для них макет не даёт. Кнопка появляется только у карточек, где есть что делать.
- **Цвет заполнения рамки** (`--color-progress`) в макете не задан: взят более насыщенный голубой, чем рамка и фон, иначе заполненная часть сливается со страницей.
- **Кнопка «←»** к списку игр над сеткой добавлена для навигации.
- **Редактор:** в макете нет кнопок прозрачности и «Начать заново», они стоят в левой колонке между «домой» и камерой. Кнопка «домой» ведёт в галерею. Цвет текста «0%» взят из токена текста, а не чисто чёрным. Шрифт Rubik Bubbles подключён локально (`@fontsource`, только латиница) и грузится вместе с редактором.
- Колонок 3 на узком экране и 4 от 640 px (в макете 4 для 844 и 1320).

## Известные ограничения

- **Имя — единственный «ключ» игрока.** Вход без пароля: кто знает имя и страну, тот входит. Игрок — пара (имя, страна): имя сравнивается без учёта регистра («ё» = «е»), одно и то же имя в другой стране — другой игрок. Разрешены только латиница, кириллица и цифры, смешивать латиницу с кириллицей в одном имени нельзя. Похожие символы внутри одного алфавита (`I` и `l`, `0` и `O`) остаются разными именами.
- **Ограничение частоты запросов** хранится в памяти одного экземпляра сервера и сбрасывается при холодном старте, а клиент определяется по `x-forwarded-for`: заголовок заслуживает доверия только за прокси, который его перезаписывает (на Vercel это делает платформа), на любом другом хостинге его можно подделать. Это базовая защита по документации `nuxt-security`; надёжный вариант потребует внешнего хранилища.
- **Вход на странице игрока без CSRF-токена.** Чужая страница может отправить форму на `/api/auth/login` и войти посетителя под выбранным именем. Документированная защита (опция `csrf` в `nuxt-security`) изменяет все формы и запросы и ждёт решения.
- **Сессия администратора живёт 8 часов** и не отзывается досрочно: cookie зашифрована и без состояния на сервере, смена пароля не закрывает уже выданные сессии.
- Сессия живёт 30 дней и привязана к cookie; удаление пользователя в админке не закроет уже выданные сессии (будет решено вместе с админкой).

- **Заливка полупрозрачной краской и прогресс.** Мягкий край кисти при 25 % даёт альфу ниже порога, поэтому узкая кромка может не считаться закрашенной.
- Область задаётся замкнутой фигурой. Линии, которые визуально делят фигуру, отдельных областей не создают.
- Текст, растровые картинки, градиенты, маски и фильтры не поддерживаются: при импорте пользователь видит предупреждение, градиенты заменяются сплошной заливкой.
- Лимиты импорта: 1 МБ, 3000 элементов, 500 областей.
